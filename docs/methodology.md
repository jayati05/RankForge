# Phase 1 methodology

The smoke fixture contains six authored documents, four queries, and four binary positive judgments. These synthetic judgments are software test expectations, never public relevance evidence. Its `test` split name is a fixture convention, not a held-out experiment. No tuning was performed for the initial smoke milestone. The subsequent public evaluation is described below.

Metrics are macro-averaged across every query with judgments in the selected split. Positive grades are relevant for Recall, Precision and MRR. Recall divides by all judged-positive documents; Precision always divides by k, even with fewer returned documents. MRR uses the first positive rank within k. nDCG uses `(2**grade - 1)/log2(rank+1)` and an ideal ranking of all judgments. Queries with no positive judgments receive zero for all metrics. Unjudged documents have zero evaluation gain; this does not assert actual irrelevance. Duplicate ranking IDs and invalid grades are errors.

Text uses NFKC normalization, case folding and Unicode tokenization preserving internal identifier separators and C++/C# suffixes. Title and body are concatenated once; no stemming or stopword removal. BM25Okapi uses k1=1.5, b=0.75, epsilon=0.25. Ties sort by document ID. Empty/tokenless and entirely out-of-vocabulary queries return no hits. For other queries, the complete corpus is ranked, including zero or negative scores, without score filtering. A tokenless corpus is rejected; individual empty documents are allowed.

Each query is timed once with perf_counter, without warmup; timing excludes data loading, index building, metric calculation and file I/O. These are first-pass timings, not steady-state performance measurements. Tiny sample latency percentiles and memory claims are omitted. No randomness is used. Input hashes, parameters, versions, platform, CPU details, query IDs and UTC timestamp accompany outputs. UUID run directories prevent accidental overwrite.

For future SciFact tuning experiments: retain the full corpus; use official train qrels for development, freezing a deterministic query-ID split and configuration before examining official test qrels. Do not subset documents to judged positives, which inflates quality. Public-data results and smoke outputs must remain separate. Actual public-data counts and filtering must be recorded after loading.

## Public-data evaluation milestone

Source is the BEIR SciFact ZIP linked by BEIR, identified by published MD5 `5f7d1de60b170fc8027bb7898e2efca1`; local archive SHA256 `536e14446a0ba56ed1398ab1055f39fe852686ecad24a6306c80c490fa8e0165` fixes the precise downloaded bytes. No semantic release number is assumed. Provenance records license/card URLs, attribution, archive and extracted-file hashes. The original SciFact claim-verification format differs from BEIR's retrieval conversion; this workflow loads the BEIR version directly without inferring claim labels or creating judgments. BEIR `test` is the retrieval benchmark split; it should not be confused with the original SciFact unlabeled claim-verification test set.

Observed data: 5,183 documents, 1,109 judged query IDs across disjoint BEIR splits. Train has 809 queries / 919 judgments; test has 300 queries / 339 judgments. All 339 test judgments are positive binary relevance labels. No document filtering, text rewriting or judgment augmentation was performed. The title+text preprocessing and metric conventions above remain unchanged.

A 25-query diagnostic subset uses ascending SHA256 of UTF-8 `42:<query-id>` (hex digest; query ID breaks any ties), followed by lexicographic query-ID evaluation order. This subset contains 26 judgments. Each selected query retains every judgment; the corpus remains complete. The full evaluation omits the limit. All selected IDs and the requested limit/seed are saved in run metadata. Subset rankings matched the same queries in the full run exactly. Selection is independent of relevance or observed scores; a 25-query sample is too small to stand in for the full benchmark.

BM25 parameters and tokenization were frozen in decisions.md before the public runs. No training or parameter tuning occurred. The test subset was used to verify execution before the complete baseline; it is not a separate held-out validation set. Since these test results have now been inspected, future choices should be made using train/development data and the final test set should be treated as an exposed benchmark, not an untouched source of evidence.

Metrics use supplied retrieval qrels only. Unjudged gain is zero, as a documented evaluation convention; judgments are incomplete and do not establish that every other scientific abstract is irrelevant. There is no significance analysis, pipeline comparison, or generalization claim beyond this corpus/split. This Python rank-bm25 implementation/tokenizer differs from other BM25 engines, so scores must not be equated with published BEIR baselines. Latency is the mean of one first-pass in-process search per query on this machine and excludes index building and I/O; it is not a production throughput or steady-state benchmark. No warm/cold comparison, p50/p95 analysis, GPU experiment or peak-memory measurement was performed.

The raw saved full-run metrics were replayed against all 300 saved rankings and original qrels, and the macro summary matched. Test cases cover parser errors, string IDs with leading zeros, multi-document relevance joins, official-split selection, deterministic query limits, whole-corpus retention, import checksums and cleanup, and saved benchmark results without any network calls.

Phase 2 adds separately documented [four-method methodology](phase2.md) without changing these metric or judgment conventions.

Phase 4 transfers the exact frozen policy to official NFCorpus test without tuning. See [external-dataset validation](external_dataset_validation.md) for pre-label registration, graded-judgment compatibility, matched within-dataset timing and unpaired cross-dataset limitations.


Phase 5 adds an independent [local HTTP service](api_service.md). It exposes rankings/overlap without qrels or relevance-quality calculations. HTTP verification compares existing saved ranks/scores for one SciFact query, not new quality scores. First-use initialization, queueing, pipeline time, payload construction and HTTP round-trip timing have distinct definitions. Shared resource order and three warm requests per method do not constitute a representative performance experiment; original scientific benchmark results and metric conventions remain unchanged.
